# 공개 QA 대화와 API

무료 QA의 자연어 명령은 웹 화면에서 처리합니다. 공개 서버는 파일 준비, QA 검사와 규칙 설명, 경고 수락·복구, XLSX 보고서를 제공합니다. `POST /api/qa/assist`는 공개 API에서 `403 qa_only`를 반환합니다. 기존 설정이나 요청 동의 값으로 생성형 모델을 호출할 수 없습니다.

용어 검사는 기존 용어집 기반 QA 엔진을 사용합니다. `check`, `review`, `report`에 선택적으로 `glossary`를 제공하며, 항목은 `source_term`과 `approved_targets`를 사용합니다. 최대 50개 항목, 항목당 승인 번역어 5개, 문자열당 150자입니다. `terminology` 범위에는 유효한 용어집이 필요합니다. 경고 처리와 보고서 요청에는 검사에 사용한 같은 용어집을 전달합니다.

배포 시 이 API를 먼저 갱신한 뒤 해당 웹 화면을 반영합니다. 제공자 설정을 켠 모의 환경에서도 공개 assist 요청이 거절되고, 준비·검사·설명·수락·복구·보고서가 제공자 없이 처리되는지 자동 테스트합니다.

## 샘플 및 보고서 언어

`POST /api/qa/prepare`에서 `action: sample`, `language: ko | en | zh-CN | zh-TW`를 받습니다. `format: rows`는 화면용 행과 용어집, `format: xlsx`는 다운로드 파일을 반환합니다. Excel의 `Source`와 `Target`은 기존 입력 계약을 따릅니다. 명시적으로 `LTLI Glossary`라는 시트가 있고 지정 헤더가 맞을 때만 그 용어집을 가져옵니다.

`report_language`를 지정하면 요약, 결과, 경고 상세 및 수락 기록을 선택 언어로 출력합니다. 생성 시각은 UTC이며 규칙 코드는 동일합니다. 공개 엔진의 경고는 동일한 심각도인 경고로 표시합니다. 원문·번역문은 문자열 셀로 기록합니다. 상세 경고가 25,000개를 초과하면 검사 범위를 줄이거나 파일을 분할하도록 안내합니다. 언어 매개변수가 생략된 API 요청은 기존 보고서 형식을 사용합니다.

규칙 설명과 보고서는 `qa_messages.json`을 사용합니다. 웹 저장소의 `app/qa-messages.json`은 동일한 카탈로그입니다.
