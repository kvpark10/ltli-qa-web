# QA 엔진·공개 API·관리자 화면 수동 자동 검사

Codex 개발 컨테이너에서 직접 실행합니다. GitHub Actions를 실행·활성화하지 않으며
운영 서버·Nginx·인증·DB·예산·환경 게시 설정을 변경하지 않습니다.
실제 AI·SMTP·Google Sheets 호출은 하지 않습니다.

## 준비와 실행

QA 저장소의 의존성과 검사를 같은 Python 3.12 가상환경에 설치합니다.
다른 앱의 가상환경을 sys.path로 섞지 않습니다. 현재 개발 경로는
`/workspace/ltli-qa-web`입니다. 새 환경에서 최초 준비할 때만 실행합니다.

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pip check
```

기존 환경에서는 아래 명령 하나로 전체 검사를 실행합니다.

```bash
.venv/bin/python scripts/check_qa_workflows.py
```

루프백 TCP 서버를 사용하는 HTTP 검사가 있으므로 컨테이너에서 로컬 소켓 생성·접속이
허용되어야 합니다. Codex 명령 샌드박스에서 로컬 소켓까지 차단된다면 해당 실행의 권한
절차를 따릅니다. 차단된 검사를 건너뛰거나 통과로 바꾸지 않습니다.
운영 서버 SSH·API 키는 필요하지 않습니다.

기본 결과 경로는 `/workspace/scratch/qa-checks/<UTC시각>-<고유값>/`입니다.
다른 위치를 지정할 수도 있으며 기존 디렉터리는 덮어쓰지 않습니다.

```bash
.venv/bin/python scripts/check_qa_workflows.py --output /tmp/ltli-qa-check-run1
```

## 보고서

| 파일 | 내용 |
|---|---|
| `report.md` | 검사 계층별 결과, 별도 확인해야 하는 범위 |
| `report.json` | SHA, 미커밋 파일 목록, 실행 위치·명령·UTC 시각, Python·패키지 버전, 개별 결과·오류·시간, 합성 샘플 소스 해시 |
| `tests.log` | 해당 실행의 unittest 출력 |

검사는 고유 ID 기준으로 한 번씩 실행합니다. 그룹별 수와 별도 재검사 수를 고유 테스트
총수에 더하지 않습니다. 통과·실패·오류·건너뜀·예상 실패·예상 밖 성공을 구분합니다.

종료 코드 0은 모든 연결된 자동 검사가 실행되고 통과했음을 뜻합니다.
실패·오류·건너뜀·예상 실패·미실행·외부 연결 시도·매핑되지 않은 테스트 모듈이 있으면 1입니다.
출력 디렉터리 생성 실패 같은 실행기 예외는 보고서 생성 전에 비정상 종료할 수 있습니다.
새 `test_*.py` 모듈을 추가할 때는 실행기의 `GROUPS`에도 검사 계층을 지정합니다.

## 검사 범위

| 그룹 | 내용 |
|---|---|
| ENGINE | 공개 QA 14개 규칙의 정상·오류 쌍, 숫자·자리표시자의 순서와 반복 횟수 |
| INPUT_REPORT | XLSX·DOCX·TXT 입력, 예상 경고·건수, 원본 불변·수정 후 재검사, Excel 문자열·수식 방지·범위 안내 |
| PUBLIC_API | 기존 엔진/API 일치, 파일 형식·한도·위험 입력 거부, 로컬 HTTP 경로·보고서·no-store, 정렬 준비 |
| REVIEW_EXPLANATION | UTF-16 경고 위치, 확인·복원, 오래된 판단 무효화, 재검사·보고서 반영, 로컬 경고 설명 |
| ADMIN_UI | Streamlit AppTest의 업로드·QA·보고서·도움말, 언어 전환과 정규 결과 보존 |
| MOCK_AI | 모의 응답 기반 도구 허용 목록·동의·상한·중복 방지·본문 비전송 |
| PRIVACY_NOTIFICATIONS | 모의 SMTP·Google 기록의 최소 정보·허용 대상·실패 처리 |
| RUNNER | 누락·빈 그룹·건너뜀·부분 실패·클래스 준비 오류의 집계, 루프백 허용 범위 |

ENGINE의 14개 규칙은 누락·원문 동일·숫자·구두점·태그·자리표시자·괄호·괄호 불균형·
URL·이메일·공백·파일명·단축키·단위입니다. 기존 내부 용어집 함수와 공개 화면 지원은
구분하며 공개 용어집 검사가 제공된다고 주장하지 않습니다.
정상·오류 쌍은 해당 규칙의 경고 유무를 확인합니다. 하나의 샘플에서 다른 규칙도 함께
경고할 수 있으므로 모든 경고가 하나뿐이라고 가정하지 않습니다.

## 외부 연결 통제

실행 중 기존 Gemini·QA 환경 설정과 Google 인증파일 선택 변수를 제거하고,
AI·이메일·Sheets 기록을 비활성 상태로 시작합니다. 개별 기존 테스트는 필요한 경우
테스트용 값과 모의 제공자·SMTP 객체를 사용합니다. 인증정보 값은 보고서에 쓰지 않습니다.

Python의 `socket.connect`와 `connect_ex`는 숫자 루프백 주소와 Unix 로컬 IPC만 허용합니다.
로컬 HTTP 검사는 임시 포트에서 서버를 열고 종료 시 정리합니다. HTTP 프록시를 거치지
않도록 루프백에 한해 `NO_PROXY`를 설정하며 외부 주소의 우회 접근은 하지 않습니다.
차단된 외부 연결 시도는 요청 자체가 실패해도 최종 결과를 실패로 처리합니다.
이 장치는 하위 프로세스까지 제한하는 OS 네트워크 샌드박스는 아닙니다.

## 자동 검사 통과에 포함되지 않는 항목

- 실제 `ltli.ai` 공개 QA와 `qa.ltli.ai` 관리자 사이트의 브라우저·인증·TLS·Nginx 연결
- 실제 브라우저의 업로드·다운로드·모바일 배치·새로고침·재연결
- Excel/LibreOffice의 시각적 표시와 사용성
- 실제 Gemini·SMTP·Google Sheets의 가용성·권한·전송 결과
- 번역 의미 정확성·문법·자연스러움·사람의 언어 검수 승인

위 항목은 보고서에 `not_run`으로 기록합니다. 공개 API의 루프백 HTTP 성공과
운영 도메인의 전체 기능 검증을 혼동하지 않습니다. 경고 없음과 사용자의 문제없음
판단 역시 의미 품질 보증이나 자동 언어 검수 승인이 아닙니다.
